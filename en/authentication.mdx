Every request carries an API key from your organisation:

```bash
Authorization: Bearer trc_live_…
```

## Test and live

| Key | Effect |
|---|---|
| `trc_test_…` | Calls are validated, nothing is sent to a person or billed. For development and testing. |
| `trc_live_…` | Calls take real effect. Refused if your organisation is not active or its trial has ended. |

## Permissions

Each key only gets the permissions it needs. A write permission includes the matching read permission.

| Permission | For |
|---|---|
| `send:read`, `send:write` | Send |
| `collect:read`, `collect:write` | Collect |
| `verify:read`, `verify:write` | Verify |
| `connect:read`, `connect:write` | Connect |
| `scan:read` | Scan |
| `webhooks:read`, `webhooks:write` | Webhooks |

## Good practice

- Keep your keys server-side, never in a mobile app or a web page.
- One key per tool: you can revoke one without touching the others.
- Revoke an exposed key immediately, from **API keys**.
