## Overview

Webhooks allow you to receive automatic notifications when an event occurs in Trayce. Instead of continuously polling the API, your backend receives an HTTP `POST` as soon as an event fires.

## Available events

| Event | Description |
|---|---|
| `collection.created` | A new Collection has been created. |
| `collection.in_progress` | The Collection has received at least one document. |
| `collection.completed` | The Collection is finalized with results. |
| `collection.review_required` | Human review is required. |
| `collection.cancelled` | The Collection was cancelled. |
| `document.received` | A new document was submitted. |
| `document.processed` | Document analysis is complete. |
| `person.completed` | All documents for a person have been received. |
| `link.accessed` | An access link was opened. |
| `link.expired` | An access link has expired. |

## Payload format

All events follow the same format:

```json
{
  "id": "evt_01HWBK",
  "event": "collection.completed",
  "created_at": "2026-10-08T14:32:00Z",
  "data": {
    "collection_id": "col_01HABC",
    "status": "COMPLETED",
    "workflow_code": "TENANT_APPLICATION"
  }
}
```

## Security

Each App has a **webhook secret** (Dashboard → Webhooks). Verify the HMAC-SHA256 signature before handling the payload:

```text
X-Trayce-Signature: t=<timestamp>,v1=<hex>
```

Recompute `HMAC_SHA256(secret, "{timestamp}.{raw_body}")` and compare to `v1`. Reject if clock skew exceeds ~5 minutes.

## Best practices

- Respond `200` within 5 seconds — process the payload in the background.
- Idempotency via `id` (retries happen).
- Use a separate App / URL for internal staging if you split environments.
