## Authentication

All API requests are authenticated by API key (Bearer token). Keys are scoped per App and per permission.

- Never expose an API key on the client side.
- Store keys in environment variables or a secrets manager.
- Use keys with the minimum required scope.
- Rotate keys regularly from the Dashboard.

## Transport

All communications between your backend and the Trayce API use **HTTPS (TLS 1.2+)**. Unencrypted HTTP requests are rejected.

## Access links

Links generated by Trayce for recipients:

- Are signed and non-guessable.
- Expire according to the configured duration (default: 7 days).
- Can be revoked at any time.
- Are single-use or multi-use depending on configuration.

## Data

- Documents are encrypted at rest and in transit.
- Document retention duration is configurable.
- Personal data is processed in compliance with applicable regulations.

## Webhooks

Verify every delivery with your App secret (`HMAC-SHA256`, `X-Trayce-Signature` header). See [Webhooks](/en/webhooks).

## API key permissions

| Permission | Access |
|---|---|
| `read` | Read Collections, Documents, Results |
| `write` | Create and modify Collections, Documents |
| `admin` | Full access, including App management |

## Vulnerability reporting

To report a security vulnerability, contact: [security@trayce.sn](mailto:security@trayce.sn)
