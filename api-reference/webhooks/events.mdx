This reference lists every event type Trayce can emit, when each one fires, and an example of the `data` object delivered with it. Use these event names when registering a webhook endpoint to control which events are delivered to your server. You can also retrieve this list programmatically via the API:

```
GET https://api.trayce.io/v1/webhooks/events
```

This endpoint returns the full set of supported event type strings for your integration, which is useful for dynamically populating subscription forms or validating event names in your code.

<Tip>
  Subscribe only to the event types your integration actually needs. Receiving a high volume of irrelevant events can strain your server and complicate your event-handling logic. You can always update your subscription by deleting and recreating the webhook with a revised `events` array.
</Tip>

## Verification Events

These events relate to identity verification sessions initiated through the Trayce platform.

### `verification.created`

Fires when a new verification session is created for a user.

**Example `data` payload:**

```json
{
  "id": "ver_04lq3n6r1eib5y9tt7sszx8whf",
  "type": "kyc",
  "status": "pending",
  "subject": {
    "name": "Jane Doe",
    "email": "jane.doe@example.com"
  },
  "created_at": "2024-05-12T08:00:00Z",
  "expires_at": "2024-05-15T08:00:00Z"
}
```

---

### `verification.in_progress`

Fires when the user has submitted their documents and automated or manual review has started.

**Example `data` payload:**

```json
{
  "id": "ver_04lq3n6r1eib5y9tt7sszx8whf",
  "status": "in_progress",
  "user_id": "usr_99ab12cd34ef56gh78ij",
  "submitted_at": "2024-05-12T08:14:00Z",
  "updated_at": "2024-05-12T08:14:00Z"
}
```

---

### `verification.completed`

Fires when the review is complete and a result is available. Check `result` to determine if the verification was approved or not.

**Example `data` payload:**

```json
{
  "id": "ver_04lq3n6r1eib5y9tt7sszx8whf",
  "status": "completed",
  "result": "approved",
  "user_id": "usr_99ab12cd34ef56gh78ij",
  "completed_at": "2024-05-12T08:27:00Z",
  "details": {
    "name_match": true,
    "document_authentic": true,
    "liveness_check": "passed",
    "risk_score": 0.04,
    "flags": []
  }
}
```

| `result` value | Meaning |
|---|---|
| `approved` | The subject passed all verification checks. |
| `rejected` | The subject did not meet the required verification criteria. |
| `manual_review` | The result requires human review before a final decision is made. |

---

### `verification.failed`

Fires when the verification could not be completed due to a technical error, an unreadable document, or a failed liveness check.

**Example `data` payload:**

```json
{
  "id": "ver_04lq3n6r1eib5y9tt7sszx8whf",
  "status": "failed",
  "user_id": "usr_99ab12cd34ef56gh78ij",
  "failed_at": "2024-05-12T08:22:00Z",
  "failure_reason": "document_unreadable",
  "failure_message": "The uploaded ID image was too blurry to process."
}
```

---

### `verification.expired`

Fires when a verification session expires because the user did not complete it within the allowed time window.

**Example `data` payload:**

```json
{
  "id": "ver_04lq3n6r1eib5y9tt7sszx8whf",
  "status": "expired",
  "user_id": "usr_99ab12cd34ef56gh78ij",
  "created_at": "2024-05-12T08:00:00Z",
  "expired_at": "2024-05-13T08:00:00Z"
}
```

## Document Events

These events relate to document requests and document deliveries.

### `document.request_created`

Fires when a new document request is created via `POST /documents/request`.

**Example `data` payload:**

```json
{
  "id": "docreq_01hx9k3m7bfz2v6pq8n4yw5tce",
  "document_type": "passport",
  "status": "pending",
  "recipient": {
    "email": "jane.doe@example.com"
  },
  "reason": "For employee onboarding at Acme Corp",
  "created_at": "2024-05-12T09:15:00Z",
  "expires_at": "2024-05-15T09:15:00Z"
}
```

---

### `document.approved`

Fires when a vault holder approves a document request, granting your organization access to the document.

**Example `data` payload:**

```json
{
  "id": "docreq_01hx9k3m7bfz2v6pq8n4yw5tce",
  "document_type": "passport",
  "status": "approved",
  "recipient": {
    "email": "jane.doe@example.com"
  },
  "approved_at": "2024-05-12T11:42:00Z"
}
```

---

### `document.rejected`

Fires when a vault holder explicitly declines a document request.

**Example `data` payload:**

```json
{
  "id": "docreq_01hx9k3m7bfz2v6pq8n4yw5tce",
  "document_type": "passport",
  "status": "rejected",
  "recipient": {
    "email": "jane.doe@example.com"
  },
  "rejected_at": "2024-05-12T10:05:00Z"
}
```

---

### `document.expired`

Fires when a document request times out before the vault holder takes action.

**Example `data` payload:**

```json
{
  "id": "docreq_01hx9k3m7bfz2v6pq8n4yw5tce",
  "document_type": "passport",
  "status": "expired",
  "recipient": {
    "email": "jane.doe@example.com"
  },
  "created_at": "2024-05-12T09:15:00Z",
  "expired_at": "2024-05-15T09:15:00Z"
}
```

---

### `document.delivered`

Fires when a document sent via `POST /documents/send` has been received and confirmed by the recipient's vault.

**Example `data` payload:**

```json
{
  "id": "docsend_02jy1l4n8cgza3w7rr5pxv6udf",
  "document_type": "diploma",
  "status": "delivered",
  "recipient": {
    "email": "jane.doe@example.com"
  },
  "sent_at": "2024-05-12T10:30:00Z",
  "delivered_at": "2024-05-12T10:31:04Z"
}
```
