---
title: "GET /verifications — List All Verifications"
sidebarTitle: "List Verifications"
description: "Retrieve a paginated list of verifications for your organization. Filter by type, status, or date range to find specific records."
---

Retrieve a paginated list of all verifications belonging to your organization. Results are returned in reverse-chronological order (newest first). Use the query parameters to filter down to specific verification types, statuses, or date ranges, and use cursor-based pagination to page through large result sets.

## Endpoint

```
GET https://api.trayce.io/v1/verifications
```

## Query Parameters

<ParamField query="type" type="string">
  Filter results to a specific verification type. One of: `kyc`, `kyb`, `diploma`, `civil_status`. Omit to return all types.
</ParamField>

<ParamField query="status" type="string">
  Filter results to verifications in a specific status. One of: `pending`, `in_progress`, `completed`, `failed`, `expired`. Omit to return all statuses.
</ParamField>

<ParamField query="from" type="string">
  Return only verifications created **on or after** this datetime. Must be a valid ISO 8601 string (e.g., `2024-01-01T00:00:00Z`).
</ParamField>

<ParamField query="to" type="string">
  Return only verifications created **on or before** this datetime. Must be a valid ISO 8601 string (e.g., `2024-06-30T23:59:59Z`).
</ParamField>

<ParamField query="limit" type="integer">
  Maximum number of verifications to return per page. Defaults to `20`. Maximum value: `100`.
</ParamField>

<ParamField query="cursor" type="string">
  Opaque pagination cursor from the `meta.cursor` field of a previous response. Pass this value to retrieve the next page of results. Omit to start from the first page.
</ParamField>

## Response

<ResponseField name="data" type="array">
  An array of verification objects matching the query. Each object has the same shape as the response from [GET /verifications/{id}](/api-reference/verifications/get), except that the `details` field is omitted for brevity. Fetch an individual verification to retrieve its full `details`.
</ResponseField>

<ResponseField name="meta" type="object">
  Pagination and result-set metadata.

  <Expandable title="meta fields">
    <ResponseField name="total" type="integer">
      Total number of verifications matching the current filter criteria (across all pages).
    </ResponseField>

    <ResponseField name="cursor" type="string">
      Opaque cursor pointing to the next page of results. Pass this value as the `cursor` query parameter in your next request. `null` when there are no further pages.
    </ResponseField>

    <ResponseField name="has_more" type="boolean">
      `true` if there are additional pages of results beyond the current response, `false` otherwise.
    </ResponseField>
  </Expandable>
</ResponseField>

  --header 'Authorization: Bearer sk_live_your_api_key_here'

To fetch the next page, pass the returned `cursor` value:

```bash
curl --request GET \
  --url 'https://api.trayce.io/v1/verifications?type=kyc&status=completed&from=2024-06-01T00:00:00Z&limit=2&cursor=cur_eyJpZCI6InZlcl8wMUhYWVo4RkdISUoiLCJkaXIiOiJuZXh0In0' \
  --header 'Authorization: Bearer sk_live_your_api_key_here'
```

<Note>
  The Trayce API uses **cursor-based pagination**, not offset-based pagination. Do not attempt to replicate pages using `limit` and an `offset` parameter — offset pagination is not supported and there is no `offset` field. Cursor-based pagination is more reliable for real-time data: it handles newly created or deleted records between pages without causing items to be skipped or duplicated. Always use the `meta.cursor` value from the previous response to advance through pages.
</Note>
