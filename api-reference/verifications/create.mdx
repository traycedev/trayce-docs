---
title: "POST /verifications — Create a Verification Request"
sidebarTitle: "Create Verification"
description: "Create a KYC, KYB, diploma, or civil status verification. Returns a verification object with an ID and pending status."
---

Use this endpoint to initiate a new identity or document verification. Trayce supports four verification types: **KYC** (Know Your Customer — individual identity), **KYB** (Know Your Business — company identity), **diploma** (academic credential verification), and **civil_status** (birth, marriage, and civil registry checks). After creation, the returned verification `id` can be shared with the subject via your application or polled directly using [GET /verifications/{id}](/api-reference/verifications/get).

## Endpoint

```
POST https://api.trayce.io/v1/verifications
```

## Request Body

<ParamField body="type" type="string" required>
  The type of verification to create. One of: `kyc`, `kyb`, `diploma`, `civil_status`.
</ParamField>

<ParamField body="subject" type="object">
  Personal details of the individual being verified. **Required** for `kyc`, `diploma`, and `civil_status` verification types.

  <Expandable title="subject fields">
    <ParamField body="name" type="string" required>
      Full legal name of the subject (e.g., `"Jane Doe"`).
    </ParamField>

    <ParamField body="email" type="string">
      Email address of the subject. At least one of `email` or `phone` must be provided so Trayce can contact the subject to complete verification.
    </ParamField>

    <ParamField body="phone" type="string">
      Phone number of the subject in E.164 format (e.g., `"+14155552671"`). At least one of `email` or `phone` must be provided.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="company" type="object">
  Business entity details. **Required** for `kyb` verification type.

  <Expandable title="company fields">
    <ParamField body="name" type="string" required>
      Legal registered name of the company.
    </ParamField>

    <ParamField body="registration_number" type="string" required>
      Official company registration or incorporation number.
    </ParamField>

    <ParamField body="country" type="string" required>
      Two-letter ISO 3166-1 alpha-2 country code where the company is registered (e.g., `"US"`, `"GB"`, `"FR"`).
    </ParamField>

    <ParamField body="vat_number" type="string">
      VAT or tax identification number. Optional, but recommended where applicable.
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="diploma" type="object">
  Academic credential details. Optional for `diploma` verification type — if omitted, the subject will be prompted to provide this information during the verification flow.

  <Expandable title="diploma fields">
    <ParamField body="level" type="string">
      Qualification level (e.g., `"bachelor"`, `"master"`, `"phd"`, `"associate"`).
    </ParamField>

    <ParamField body="institution" type="string">
      Name of the awarding institution (e.g., `"Massachusetts Institute of Technology"`).
    </ParamField>

    <ParamField body="graduation_year" type="integer">
      Four-digit year of graduation (e.g., `2019`).
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="callback_url" type="string">
  A valid HTTPS URL to which Trayce will deliver webhook events when the verification status changes. Must begin with `https://`. See the [Webhooks](/api-reference/webhooks) guide for event payload details.
</ParamField>

<ParamField body="metadata" type="object">
  Arbitrary key-value pairs you want to store alongside the verification. Values must be strings. Useful for attaching your own internal identifiers (e.g., `{"user_id": "usr_9x2k", "order_ref": "ORD-4821"}`). Maximum of 20 keys, each key ≤ 40 characters, each value ≤ 500 characters.
</ParamField>

<ParamField body="expires_in" type="integer">
  Number of seconds from now until the verification request expires. Defaults to `259200` (72 hours). Minimum value: `3600` (1 hour). After expiry, the verification moves to `expired` status and cannot be completed.
</ParamField>

## Response

<ResponseField name="id" type="string">
  Unique identifier for the verification (e.g., `"ver_01HXYZ9ABCDE"`). Use this ID to retrieve status updates via [GET /verifications/{id}](/api-reference/verifications/get).
</ResponseField>

<ResponseField name="type" type="string">
  The verification type as provided in the request (`kyc`, `kyb`, `diploma`, or `civil_status`).
</ResponseField>

<ResponseField name="status" type="string">
  Initial status of the verification. Always `"pending"` immediately after creation — the subject has not yet taken action.
</ResponseField>

<ResponseField name="created_at" type="string">
  ISO 8601 timestamp of when the verification was created (e.g., `"2024-06-15T10:32:00Z"`).
</ResponseField>

<ResponseField name="expires_at" type="string">
  ISO 8601 timestamp of when the verification will expire if not completed.
</ResponseField>

<ResponseField name="subject" type="object">
  Echo of the `subject` object provided in the request. Present for `kyc`, `diploma`, and `civil_status` types.
</ResponseField>

<ResponseField name="company" type="object">
  Echo of the `company` object provided in the request. Present for `kyb` type.
</ResponseField>

<ResponseField name="metadata" type="object">
  The metadata key-value pairs stored with this verification.
</ResponseField>

## Example

<CodeGroup>

```bash cURL
curl --request POST \
  --url https://api.trayce.io/v1/verifications \
  --header 'Authorization: Bearer sk_live_your_api_key_here' \
  --header 'Content-Type: application/json' \
  --data '{
    "type": "kyc",
    "subject": {
      "name": "Jane Doe",
      "email": "jane.doe@example.com",
      "phone": "+14155552671"
    },
    "callback_url": "https://app.example.com/webhooks/trayce",
    "metadata": {
      "user_id": "usr_9x2k",
      "order_ref": "ORD-4821"
    },
    "expires_in": 86400
  }'
```

</CodeGroup>

<Note>
  In the **sandbox environment** (`https://sandbox.api.trayce.io/v1`), verifications return instant mock results rather than entering a real review workflow. Use sandbox `sk_test_` keys during development to simulate `approved`, `rejected`, and `manual_review` outcomes without triggering live checks. Use the sandbox environment during development to iterate quickly without affecting production data.
</Note>
