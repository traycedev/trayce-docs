Retrieve the current state of a single verification using its unique ID. This endpoint returns the full verification object, including result and type-specific details once the verification has reached `completed` status. You can use this endpoint to poll for updates, though [webhooks](/api-reference/webhooks) are the recommended approach for production systems.

## Endpoint

```
GET https://api.trayce.io/v1/verifications/{id}
```

## Path Parameters

<ParamField path="id" type="string" required>
  The unique identifier of the verification to retrieve (e.g., `ver_01HXYZ9ABCDE`). This is the `id` returned when the verification was [created](/api-reference/verifications/create).
</ParamField>

## Response

<ResponseField name="id" type="string">
  Unique identifier for the verification.
</ResponseField>

<ResponseField name="type" type="string">
  The verification type: `kyc`, `kyb`, `diploma`, or `civil_status`.
</ResponseField>

<ResponseField name="status" type="string">
  Current lifecycle status of the verification. One of: `pending`, `in_progress`, `completed`, `failed`, or `expired`. See [Verification Statuses](#verification-statuses) for a full description of each state.
</ResponseField>

<ResponseField name="result" type="string">
  The outcome of the verification. Only present when `status` is `"completed"`. One of: `approved`, `rejected`, or `manual_review`.
</ResponseField>

<ResponseField name="created_at" type="string">
  ISO 8601 timestamp of when the verification was created.
</ResponseField>

<ResponseField name="completed_at" type="string">
  ISO 8601 timestamp of when the verification reached a terminal status (`completed`, `failed`, or `expired`). `null` if the verification is still in progress.
</ResponseField>

<ResponseField name="details" type="object">
  Type-specific verification details populated after the verification completes. The structure varies by verification type.

  <Expandable title="details fields">
    <ResponseField name="document_type" type="string">
      *(KYC only)* The type of identity document verified (e.g., `"passport"`, `"national_id"`, `"drivers_license"`).
    </ResponseField>

    <ResponseField name="document_country" type="string">
      *(KYC only)* ISO 3166-1 alpha-2 country code of the issuing authority.
    </ResponseField>

    <ResponseField name="document_expiry" type="string">
      *(KYC only)* Expiry date of the identity document in `YYYY-MM-DD` format.
    </ResponseField>

    <ResponseField name="date_of_birth" type="string">
      *(KYC only)* Date of birth extracted from the identity document in `YYYY-MM-DD` format.
    </ResponseField>

    <ResponseField name="institution_confirmed" type="boolean">
      *(Diploma only)* Whether the issuing institution confirmed the credential.
    </ResponseField>

    <ResponseField name="registry_reference" type="string">
      *(Civil status only)* Reference number from the civil registry.
    </ResponseField>

    <ResponseField name="rejection_reasons" type="array">
      Array of reason codes explaining why the verification was rejected or flagged for manual review (e.g., `["document_expired", "face_mismatch"]`). Empty array if the result is `approved`.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="subject" type="object">
  The subject details associated with the verification. Present for `kyc`, `diploma`, and `civil_status` types.
</ResponseField>

<ResponseField name="company" type="object">
  The company details associated with the verification. Present for `kyb` type.
</ResponseField>

<ResponseField name="metadata" type="object">
  The metadata key-value pairs stored with the verification.
</ResponseField>

## Verification Statuses

| Status | Description |
|---|---|
| `pending` | The verification has been created but the subject has not yet taken any action. |
| `in_progress` | The subject has submitted their documents or information and the review is underway. |
| `completed` | The verification has finished. Check the `result` field for `approved`, `rejected`, or `manual_review`. |
| `failed` | The verification could not be completed due to a technical error or an unrecoverable submission problem. |
| `expired` | The verification was not completed before the `expires_at` deadline. |

<Tip>
  For production integrations, we strongly recommend using **webhooks** instead of polling this endpoint. Webhooks deliver real-time status updates to your `callback_url` the moment a verification transitions state, removing the need for repeated API calls. See the [Webhooks](/api-reference/webhooks) guide to get started.
</Tip>
